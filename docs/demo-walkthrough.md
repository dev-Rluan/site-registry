# 데모 따라하기

목적은 **사람의 승인을 받은 근거를 AI의 기준 자료로 제공하고, 분석이 사용한 근거를 나중에도 확인하는 구조**를 실행해 보는 것입니다. 모든 업무 내용·승인자·토큰은 가상이며 모델 호출 결과가 아닙니다.

## 1. 실행

Node.js24 환경에서 저장소 루트의 `npm run demo`를 실행하고 <http://127.0.0.1:4174>를 엽니다. 처음부터 예시를 보려면 비어 있는 새 데이터 폴더를 지정합니다.

```sh
SITE_REGISTRY_DATA_DIR="$PWD/.data/demo-fresh" npm run demo
```

같은 폴더로 다시 시작하면 수정 내용이 유지됩니다. 예전 v0.1 데모 DB에는 새 예시가 자동으로 추가되지 않으며, 자료는 사람이 승인할 때까지 미승인입니다.

## 2. 최신 초안과 기준본을 구분

알파 주문 사이트의 **근거맵** 탭에서 다음을 확인합니다.

- 업무 정책·필드 문서·원데이터·검토 기준의 승인된 v1
- 중복 승인 검토 기능의 **v1 승인 + v2 초안**
- 비공유·미승인 검토 메모

기능의 v2 초안이 존재해도 **MCP 미리보기와 기능맵에는 승인된 v1**이 나옵니다. 초안과 비공유 메모는 AI가 사용할 기준본에 섞이지 않습니다. JSON 다운로드로 승인 노드와 `references` 간선도 확인할 수 있습니다.

## 3. 사람의 검토·승인

기능 v2의 내용을 읽고 **검토·승인**을 누릅니다. 검토자 이름, 검토 의견과 결과를 입력합니다. 승인 후에는 MCP 미리보기와 기능맵의 기준본이 v2로 바뀝니다.

이름은 직접 적는 기록으로, 로그인한 사용자의 신원을 검증하지 않습니다. 데모 승인은 권한 관리 제품을 시연하는 것이 아니라 버전별 검토 절차를 보여줍니다. 반려를 선택하면 v2는 반려본으로 남고 v1이 기준을 유지합니다.

## 4. 분석 결과와 근거 스냅샷

**분석 이력**의 가상 요청을 봅니다.

> 금액이 같은 승인 이벤트를 모두 중복으로 판단해도 되는가?

미리 작성한 결과는 “금액만으로 확정하지 말고 주문번호·승인번호·승인 완료 상태를 확인”하라고 안내합니다. 기록에는 다음 항목이 포함됩니다.

- 원 요청, 요구사항 또는 리스크 모드, 결과와 분석 출처
- 분석 자체의 버전과 시각
- 사용한 근거의 정확한 자료 ID·버전
- 사용 당시 제목·본문·출처·승인 정보 스냅샷

기능 v2를 승인했더라도 기존 분석이 사용한 v1 스냅샷은 바뀌지 않습니다. **새 버전 작성**으로 분석을 갱신하면 기존 분석 버전도 남습니다. 참조 근거는 하나 이상 선택해야 하며 같은 사이트의 승인·공유 자료만 사용할 수 있습니다.

## 5. 새 기능 초안 등록

기능 정의 종류를 선택하고 다음 예시를 입력합니다. `related_ids`는 화면에서 확인한 같은 사이트의 실제 자료 ID로 바꾸거나 빈 배열로 시작합니다.

```json
{
  "summary": "승인 이벤트 검토 결과를 안내하는 기능",
  "rules": ["확정 판정과 검토 필요 상태를 구분한다.", "참조한 정책의 출처를 안내한다."],
  "related_ids": []
}
```

제목과 출처를 입력하고 저장합니다. 화면에서 등록한 자료는 공유 대상으로 저장되지만, 초안이므로 기준맵에 나타나지 않습니다. 사람 검토·승인 후에만 기준 근거가 됩니다. 이미 승인한 자료를 수정할 때도 원래 승인본을 덮어쓰지 않고 새 초안을 만듭니다.

## 6. 사이트·배치 경계 확인

**사이트·배치** 탭에서 알파의 일일 승인 동기화 메타데이터를 봅니다. 설명·주기는 공개 정보이고 배치 인증정보는 암호화한 채 반환하지 않습니다. 여기서 배치를 실행하지는 않습니다. 사이트 전체 설정은 별도의 **암호화 설정** 탭에서 보관합니다.

베타 사이트로 전환하면 다른 예약 정책과 배치만 보입니다. 알파의 자료 ID를 베타 기능에 연결하거나 다른 사이트 자료를 분석 근거로 저장할 수 없습니다.

## 7. 실제 /site로 연결할 때

[연결 방법](mcp-workflow.md)에 따라 `.mcp.json`과 Skill을 복사합니다. 예시와 다른 데이터 폴더를 사용했다면 MCP도 같은 절대 경로를 지정합니다.

```text
/site 요구사항 금액이 같은 승인 이벤트를 모두 중복으로 판단해도 되는가?
/site 리스크 승인 이벤트의 금액만으로 중복을 판정하도록 변경할 때의 위험을 검토해줘
/site 초안 현재 코드의 승인 이벤트 검토 기능을 분석해 기능 정의 초안으로 저장해줘
```

Skill은 승인 근거·검토 기준을 읽고 출처·버전을 인용하도록 안내합니다. 실제 코드에 접근할 수 없는 경우 코드를 분석한 것처럼 작성하지 않도록 지시합니다. MCP에는 초안과 분석 저장만 있고 승인 도구는 없습니다. 사람이 화면에서 내용을 확인하고 승인합니다.

실제 Claude Code 연결, 생성 결과의 정확성, 업무 시간 절감 효과는 이 웹 데모만으로 검증되지 않습니다.
