# 동작·성능·AI 효율 검증

검증일: 2026-10-31. 모든 업무 자료와 사건은 가상입니다.

## 확인한 결과

실제 Claude Code의 `/site`가 MCP로 승인 근거를 조회하고 분석 1건을 저장했습니다. 같은 모델의 8문항 × 2조건 비교에서는 승인본만 제공했을 때 **입력 토큰이 22.4% 줄었습니다.** 평균 응답 시간은 두 조건 모두 약 10초였습니다. 36개 업무 판단 항목의 AI 보조 검토는 전체 버전 33/36, 승인 근거 34/36이었으며, 중요한 오판을 확인하는 17개 항목은 두 조건 모두 통과했습니다.

이 결과는 가상 8문항의 탐색 평가입니다. 품질 우위나 일반적인 업무 생산성 향상을 확정하지 않습니다. 사람의 채점·운영 데이터 검증은 수행하지 않았습니다.

## 실제 Skill → MCP → 저장

모델 `claude-sonnet-5-5`, Claude Code `2.1.316 (Claude Code)`로 가상 알파 사이트의 동일 금액 승인 이벤트를 검토했습니다.

1. `/site` Skill 발견
2. `list_sites`, `get_site_context`, `get_feature_map` 실제 성공 호출
3. `record_analysis` 실제 성공 호출과 분석 1건 저장
4. 저장된 분석의 근거 ID·정확한 승인 버전·본문·출처 일치 확인
5. 다른 사이트 정책·비공유 메모·가상 비밀값이 모델 스트림에 없음을 확인

소요 시간은 **15.565초**였습니다. 모델은 금액만 같은 A-101/OK-01과 A-102/OK-02를 중복으로 확정하지 않았고, 운영 코드·로그를 확인하지 않았음을 명시했습니다. 이 흐름은 요구사항 검토 한 번이며 기능 초안 생성·리스크 모드의 전체 도구 흐름까지 검증한 것은 아닙니다.

전체 도구 왕복의 누적 입력 토큰은 35,483, 출력 토큰은 1,597이었습니다. 기본 시스템 지침·Skill·도구 정의와 반복 입력이 포함되므로 아래 고정 입력 A/B와 직접 비교하지 않습니다. CLI 비용 추정은 $0.07287이며 실제 청구액이 아닙니다.

원자료: [claude-mcp-smoke.json](claude-mcp-smoke.json)

## 실제 모델 A/B

두 조건 모두 `claude-sonnet-5-5`를 사용했습니다. 각 질문마다 새 세션을 사용하고 실행 순서를 교차했습니다. RAW에도 승인 상태·사이트·버전·출처를 제공해 모델이 승인본을 스스로 구분할 수 있도록 했습니다. 채점 기준은 생성 모델에 제공하지 않았습니다.

| 8문항 합계 또는 평균 | 전체 공유 버전 | 승인 근거만 |
|---|---:|---:|
| 총 입력 토큰 | 27,632 | 21,432 |
| 일반 입력 토큰 | 16 | 16 |
| 캐시 생성 입력 토큰 | 27,616 | 21,416 |
| 캐시 읽기 입력 토큰 | 0 | 0 |
| 출력 토큰 | 8,182 | 8,352 |
| 평균 전체 경과 시간 | 9.871초 | 9.955초 |
| 평균 API 처리 시간 | 8.749초 | 8.859초 |
| CLI 비용 추정 합계 | $0.192316 | $0.169216 |
| 업무 판단 항목 통과 | 33/36 | 34/36 |
| 중요 항목 통과 | 17/17 | 17/17 |

총 입력은 일반 입력 + 캐시 생성 + 캐시 읽기의 합입니다. `input_tokens` 필드 하나만 비교하지 않았습니다. [공식 토큰 집계 설명](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

입력은 22.4% 감소했고, CLI 비용 추정은 12.0% 낮았습니다. 비용은 캐시 정책·출력 길이·계정 조건의 영향을 받는 클라이언트 추정치이며 실제 청구 절감률로 사용하지 않습니다. 승인 근거 조건의 출력 토큰은 약 2.1% 많았고, 평균 경과 시간은 약 0.084초 길었습니다. 반복 측정이 없어 응답 속도 개선은 확인하지 못했습니다.

양쪽 모두 같은 1,200자 이내 분량 지침을 받았지만 이는 하드 토큰 제한이 아닙니다. 실제 평균 길이는 약 1,140자였고, 두 조건 각각 2개 답변이 지침을 넘었습니다. 입력 선별 효과, 출력 분량 준수, 업무 판단 품질을 구분합니다.

원자료: [16개 응답과 사용량](claude-ab-evaluation.json) · [수치 요약](model-evaluation-summary.json)

## 답변 검토와 부족한 점

질문은 기존 기능 안내, 취소 이벤트로 확장, 자동 환불 신규 요구, 같은 금액의 오판, 사이트 정책 혼용, 최신 초안 승격, 운영 근거 부족, 배치 등록과 실행 구분의 8개입니다. [질문·채점 기준](../evaluation/cases.json)

별도 AI 검토자가 조건 이름·시간·사용량을 가린 답변에 대해 36개 항목을 각각 판단했습니다. 제공 근거 목록으로 조건을 추측할 수 있는 한계는 있습니다. 사람이 직접 채점한 결과가 아닙니다. 경계가 모호한 테스트 제안 2개는 통과로 올리지 않고 미통과와 사람 검토 대상으로 유지했습니다.

- 두 조건 모두 운영 사건을 지어내거나 동일 금액만으로 중복을 확정하지 않았습니다.
- 두 조건 모두 승인 취소 범위 확장 시 검증할 테스트 사례가 충분히 명확하지 않았습니다.
- 두 조건 모두 복구 영향 범위·정상값·사전 검증 절차의 안내가 부족했습니다.
- 전체 버전 조건의 답변 1개는 원데이터의 ID·버전은 맞았지만 출처 필드 인용이 빠졌습니다.

이번 차이는 출처 인용 한 항목입니다. 1개 항목 차이로 일반적인 품질 향상을 주장하지 않습니다. 후속 개선은 출처 필드의 구조화, 검증 테스트·복구 검토 항목의 명시화입니다.

원자료: [항목별 판정과 이유](model-quality-review.json)

## 로컬 서버 성능

Node.js 24.22.1 / macOS arm64 / Apple M2 Pro에서 측정했습니다. 자료마다 3개 버전이 있고, 전체 자료의 70%가 공유 가능한 승인 기준본을 갖도록 구성했습니다. 5회 워밍업 후 40회 순차 요청의 p95입니다. 응답 파싱과 경계 검증 시간도 포함하며 동시 사용자 부하 시험은 아닙니다.

| 자료 수 / 전체 버전 | Store p95 | HTTP p95 | 실제 stdio MCP p95 |
|---|---:|---:|---:|
| 10개 / 30버전 | 0.348ms | 1.238ms | 0.567ms |
| 100개 / 300버전 | 2.806ms | 3.907ms | 3.791ms |
| 500개 / 1500버전 | 15.760ms | 19.063ms | 17.433ms |

500개에서 새 MCP 프로세스 시작부터 첫 컨텍스트까지 p95는 **54.956ms**였습니다. 새 프로세스 5회, OS 파일 캐시는 이미 따뜻한 상태입니다.

| 500개 자료의 출력 | UTF-8 크기 |
|---|---:|
| 같은 사이트의 전체 1,500버전, 동일 필드 | 1,155,943B |
| 승인·공유 기준본 350개, 동일 필드 | 273,897B |
| 사이트·배치·검토 기준까지 포함한 전체 컨텍스트 JSON | 313,758B |
| 실제 MCP 응답, 프로토콜·들여쓰기·escape 포함 | 364,094B |

동일 필드 자료량은 **76.305% 감소**했습니다. 인위적인 버전·승인·공유 비율에 따른 결과이며, 위 8문항의 실제 모델 입력 토큰 감소율과 다른 측정입니다. 사이트·비밀값 경계와 이전 승인본 유지 assertion도 모두 통과했습니다. [원자료](runtime-benchmark.json)

## 재현

모델을 호출하지 않는 검증:

```sh
npm test
npm run benchmark
npm run eval:prepare
```

실제 모델 호출은 유효하게 로그인한 Claude Code와 설정된 계정 사용량을 사용합니다. 모든 테스트 DB는 가상 데이터로 별도 생성하며 사용자 DB를 수정하지 않습니다.

```sh
npm run smoke:claude
npm run eval:claude -- --run
```

A/B는 16회 호출하며 호출당 CLI 비용 추정 상한은 $0.50입니다. smoke는 1회, $0.80입니다. 이 상한은 구독 사용량·청구액을 보장하는 제한이 아닙니다. `sonnet` 별칭으로 요청하고 실제 모델 식별자는 JSON에 보존합니다. 유효한 로그인 표시는 실제 요청의 인증 성공을 대신하지 않습니다.

실행 스크립트는 원문 측정 JSON을 갱신합니다. 이 문서·수치 요약·의미 기반 채점은 위 검증일의 결과 기록이므로 새 실행 후 별도 갱신이 필요합니다. 사용자 메일·키·인증 토큰·원문 세션 로그는 공개 결과에 넣지 않습니다.

## 남은 한계

- 자료를 검색하는 검색기는 없습니다. 자료가 늘면 사이트의 승인본 전체를 전달합니다.
- 실제 Skill은 컨텍스트와 기능맵을 모두 읽어 본문이 중복될 수 있습니다. 고정 입력 A/B는 중복을 피하려고 `get_site_context`만 사용했고 도구는 껐습니다.
- 같은 모델·질문·공통 지침의 조건별 1회 탐색 평가입니다. 통계적 유의성·업무 시간·운영 정확도를 보증하지 않습니다.
- 사람의 승인은 사실 정확성의 자동 보증이 아닙니다. 실제 업무 자료로 추가 검토해야 합니다.
- 다중 사용자, 원격 배포, 운영 부하, 여러 MCP 클라이언트, 실제 코드 분석·기능 초안 생성의 전체 흐름은 이번 범위에 포함하지 않았습니다.
