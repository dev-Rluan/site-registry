# v0.2 검증 결과

검증일: 2026-10-31. Node.js 24.22.1, macOS, 가상 데이터로 확인했습니다.

## 자동 테스트

`npm test`의 **15개 테스트가 모두 통과**했습니다. `test/registry.test.js`의 8개와 `test/workflow.test.js`의 7개입니다.

| 범위 | 확인한 내용 |
|---|---|
| 암호화·키 | 무작위 암호문, 정상 복호화, 잘못된 키·인증 태그 변조·다른 사이트 인증 데이터 거부, 자동 키 재사용과 0600 권한 |
| 설정 저장 | config 평문 미저장·응답 제외, 버전 보존, 오래된 버전 갱신 거부, 키 불일치 검사 |
| 사이트 경계 | 다른 사이트 자료 수정·기능 관계·분석 참조 거부, MCP 사이트 선택 인자 거부 |
| 승인 기준본 | 초안은 미제공, 정확한 최신 초안만 검토, 결정 불변, 수정·반려 중 기존 승인본 유지, 새 버전 승인 후 교체 |
| 근거맵 | 기능 JSON 구조 검사, 승인·공유 노드만 반환, 미승인 노드로의 간선 제외 |
| 배치 정보 | 메타데이터만 반환, 비밀값 암호화와 DB 평문·조회 응답 제외 |
| 분석 기록 | 승인·공유된 정확한 근거 버전만 참조, 사용 당시 본문·출처 스냅샷 보존, 분석 새 버전과 충돌 검사 |

| 실제 stdio MCP | 초기화·목록·조회·초안 저장·분석 기록, 승인 도구·임의 상태·공유 여부·사이트 변경 인자 거부 |
| HTTP | 사이트 등록, 설정·자료 저장, 사람 검토 기록, 근거맵·분석·배치 API, 외부 Origin·중복 코드 거부 |

위 테스트는 정해진 입력과 경로를 확인합니다. 포괄적인 보안 감사, AI 판단 정확도, 승인자 신원 인증을 입증하지 않습니다.

## 브라우저 검수

실제 Chrome headless에서 다음 흐름을 확인했습니다.

1. 가상 데이터의 v1 승인본과 v2 초안을 구분하고, MCP에는 v1만 제공되는지 확인
2. 승인 근거맵 JSON 다운로드
3. 새 정책 초안 등록 → v1 승인 → v2 수정 → v2 반려 → v3 수정·승인. 중간에는 v1 기준 유지
4. 승인된 정확한 버전으로 분석 등록, 근거 스냅샷 확인, 분석 v2 작성
5. 배치 등록과 비밀값의 화면·맥락 응답 제외
6. 베타 사이트에서 알파 자료가 섞이지 않는지 확인
7. 390×844 모바일의 가로 넘침 없음, 브라우저 JavaScript 오류 없음

이 화면은 실제 LLM 응답 생성이 아니라 수동 작성한 가상 예시와 UI 동작입니다.

## 최초 실행 확인

빈 임시 폴더에서 실제 서버를 실행해 가상 사이트 2개 생성, 승인 근거 제공, 키 파일의 0600 권한을 확인했습니다. 종료 후 재시작해 데이터가 유지되며, 데모와 일반 실행의 저장소가 분리되는 것도 확인했습니다. 외부 패키지는 설치하지 않았습니다.

## 추가 성능·연결 확인

실제 디스크 SQLite·HTTP·별도 stdio MCP 프로세스로 자료 10/100/500개를 측정했습니다. [동작·성능·AI 효율 검증](evaluation.md)에 결과와 재현 방법을 기록했습니다. Claude Code에서 `/site`가 실제 MCP 조회 3개와 분석 저장을 수행했고, 정확한 승인 근거 버전이 DB에 기록되는 것까지 확인했습니다. 가상 8문항 × 2조건의 모델 응답도 수집했습니다.

## 확인하지 않은 것

- 실제 코드 분석·기능 초안 생성 모드와 다양한 MCP 클라이언트
- 실제 업무 자료의 분석 정확도, 일반화된 업무 시간·비용 절감
- 다중 사용자, 인증·권한, 원격 배포, 운영 부하, KMS·키 회전·백업 복구

MCP는 초안·분석을 저장하기 위해 SQLite 쓰기 권한을 갖습니다. 승인과 비밀값 조회를 제공하지 않는다는 제한은 MCP 도구 수준의 경계입니다. 동일 OS 사용자로 로컬 웹 API나 DB 파일에 직접 접근하는 프로그램까지 격리하지 않습니다.
